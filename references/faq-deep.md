# 深度 FAQ（边缘场景）

> 主文档 FAQ 覆盖通用问题，这里补齐垂直领域适配、工具 / 平台兼容、定制化、数据安全、商用授权等边缘场景。

**D1 不同垂直领域怎么设 `--dimensions`？**
抓"下次同类任务你最想直接拿来用的那几个维度"，不要贪多：
- 分析报告类：`市场定位,功能对比,定价策略`
- 代码类：`模块边界,依赖,测试策略`
- 运维类：`排查路径,根因分类,回滚方案`
- 写作类：`结构骨架,风格锚点,素材来源`

**D2 能和 Obsidian / 飞书 / Notion 打通吗？**
当前库是纯 JSON 文件，不自动同步到这些平台。可行做法：把 `skill_library.json` 放进 Obsidian Vault 目录用双链引用；或写个小脚本把条目转成 Notion / 飞书数据库行。需要的话在 issues 提需求。

**D3 怎么和向量库（COS / BGE）配合做语义检索？**
`find` 是字符匹配。语义召回两步走：① 用 `--tags` 建同义词标签组兜底；② 把条目文本送 BGE 向量化存入 COS 向量桶，检索时先向量召回再回查本库取 `approach`。**本库负责"存与棘轮"，语义检索交给向量层。**

**D4 商用授权？**
MIT。可商用、可修改、可再分发，只需保留版权声明与 LICENSE；不对适用性作担保。库里是你自己的经验数据，归属你自己。

**D5 库里误存了密钥 / 个人信息怎么办？**
- 单条：`get --id <id>` 确认后 `optimize` 改掉敏感字段，或手动编辑库文件删该条目；
- 整库：直接删 `skill_library.json`，下次命令自动新建空库（已落盘的 `*.tmp` 原子文件可改名恢复）。
- 预防：见 anti-patterns 反模式 3，条目只存拆解经验。

**D6 每个项目用独立库怎么组织？**
用 `--store` 给项目开独立库：
```bash
python scripts/library.py --store ./project_a/lib.json add --task-type demo --description "写周报" --approach "进展→风险→计划" --tags "report" --score 0.6
```
CI / 收尾自检对各自库跑 `guard`。建议各项目库放项目根或 Vault，别混进一个全局库。

**D7 多 Agent（hermes / qclaw / workbuddy）能共享一个库吗？**
能但需串行：并发写同一 `--store` 会读过期数据、丢条目（见主文档 Q8）。推荐各自独立 `--store`，需要汇聚时由一个 Agent 负责 merge，或都接 COS 向量桶做共享检索层。

**D8 库文件能 git 提交 / 跨机同步吗？**
能，纯 JSON、无状态。直接提交即可版本化你的经验演进；跨机同步用现有同步工具（如 Obsidian Vault / workbuddy-sync）。注意：含敏感信息的库不要提交到公开仓库。

**D9 v1.2.x 老库升级到 v1.3.0 兼容吗？**
兼容。v1.3.0 的 `lifecycle` 字段对老条目自动补齐（缺即 OPEN，`guard` 会提示你走完闭环）；`meta.steps` 老库默认为 0。无需手动迁移。

**D10 条目上千后 `find` 会慢吗？**
字符 + 标签匹配是 O(n)，上千条仍毫秒级，日常够用。若到万级且要语义召回，按 D3 接向量库，本库退化为"权威存储 + 棘轮"。
